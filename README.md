# A Visual Explainable-AI Framework for Step-Level Plantar Pressure and Temperature Gait Analysis Using Dynamic Time Warping

A reproducible, exploratory pipeline for **wearable gait analysis** that couples
**plantar pressure** and **plantar temperature** with **Dynamic Time Warping (DTW)**
and **explainable machine learning (SHAP)**. The pipeline treats its *visual outputs*
— DTW alignments, SHAP attributions, and regional distribution maps — as the primary
deliverable for biomechanical interpretation, rather than as a black-box classifier.

This repository accompanies a manuscript prepared for *Visual Computing for Industry,
Biomedicine, and Art* (VCIBA). It contains the analysis code and a portable
reproducibility pipeline that regenerates every reported statistic and data-driven
figure from the released artefacts.

> **Scope & intent.** This is an *exploratory, hypothesis-generating* study, not a
> clinical diagnostic test. Anomaly labels are derived from the step features
> themselves (multi-feature z-score rules); the machine-learning models are used as a
> *scaffold* that makes the SHAP feature attribution meaningful.

## Dataset and authenticity

The dataset is a **genuine clinical sensor dataset**, not synthetic or simulated data.

- **Owner / source:** Middlesex University London. The data were **provided by
  Dr Clifford De Raffaele** (Middlesex University London) and were originally recorded
  during **patient clinical trials** using a custom smart-insole system.
- **Sensing hardware:** **FlexiForce A401** force sensors embedded in a custom smart
  insole, with **four pressure regions** and **four temperature regions** per foot:
  R1 (toe), R2 (mid-foot), R3 (lateral) — the forefoot "metatarsal" sensors — and
  R4 (heel).
- **De-identification:** the author received the data in fully de-identified form.
  **All demographic and clinical attributes (age, sex, gender, history) were withheld**
  for patient-data protection and were never available to the author; only anonymised
  sensor signals and non-identifying participant indices were shared.
- **Units:** pressure is reported in the insole's **raw, uncalibrated sensor counts**,
  so values support *relative* comparison across regions/participants rather than
  absolute force.
- **Scale:** 312 participants in the raw export (93,790 observations) → filtered to a
  final analysis cohort of **67 participants / 58,807 observations** (see below).

No new data collection or participant recruitment was performed for this study. See
**[Data availability](#data-availability)** for redistribution constraints.

## Methodology

The pipeline runs in stages (full interactive version in `4090_s2-2.ipynb`):

1. **Cleaning & unit handling.** Temperature is constrained to a physiological window
   (15–45 °C); pressure saturation artefacts are handled (raw counts retained for
   relative analysis).
2. **Cohort selection (two stages).**
   - *Stage 1 — variability filter:* keep a participant if any channel meets
     `std ≥ 10`, `range ≥ 50`, or rate-of-change variability `≥ 2` → **92 / 312**.
   - *Stage 2 — coverage filter:* keep participants with **≥ 25 valid detected steps**
     → **67 participants, 58,807 observations**.
3. **Step segmentation & metrics.** Each detected step is summarised by **seven
   metrics**: peak pressure, area under curve (AUC), rise gradient, descent gradient,
   variance, skewness, and kurtosis.
4. **Two-stage baselines.**
   - *Cohort baseline* (coarse, screening only).
   - *Stepwise regional baseline* (the reference used for all reported results).
5. **Anomaly labelling.** Multi-feature **z-score rules** flag candidate anomalous
   steps per region.
6. **Explainable modelling.** **Random Forest** and **XGBoost** are trained to recover
   the statistical anomaly boundary under **5-fold stratified cross-validation**; this
   confirms the labels are learnable/stable enough to support **SHAP** attribution.
7. **DTW alignment.** Steps of unequal length are aligned to the regional baseline
   template; warping distance exposes temporal phase shifts (heel→toe load transfer)
   that linear correlation misses.
8. **Visual explainability.** SHAP summaries, DTW alignment plots, and regional
   distribution maps are produced as the interpretable, clinician-facing outputs.

## Key findings

All values below are regenerated by `repro/regenerate_stats.py`
(see `repro/canonical_stats.json`).

**Regional load (stepwise-baseline peak pressure, sensor counts)**

| Region | Mean | Std | Baseline steps |
|--------|------|-----|----------------|
| R1 — Toe | 80.52 | 18.80 | 92 |
| R2 — Mid-foot | 57.78 | 30.44 | 149 |
| R3 — Lateral | 45.28 | 33.95 | 185 |
| **R4 — Heel** | **112.58** | 46.49 | 134 |

- The **heel (R4) consistently carries the largest peak load** — ~40% higher than the
  next region — and the difference across regions is significant
  (one-way ANOVA **F = 107.61, p < 1e-50**).
- **Pressure** varies strongly by region/step (raw per-channel **CV ≈ 4.8 – 18.3**),
  while **temperature** is smooth and near-monotonic (cleaned means 23.95–25.04 °C,
  std 3.82–4.17; 62–84% of readings within the physiological window).
- **Cross-region structure is temporal, not linear.** Step-index-aligned baseline
  correlations are exploratory (R1–R4 = **−0.34**, R2–R4 = **0.29**, R1–R3 = **0.30**),
  but raw per-sample correlation is near zero (R1–R4 ≈ **0.006**). DTW reveals the real
  signal: a **temporal offset** between heel and toe loading.
- **Explainable models recover the anomaly boundary** under 5-fold stratified CV
  (weighted F1): **R2 RF = 0.953 ± 0.042**, R3 RF = 0.900 ± 0.072,
  R4 RF = 0.883 ± 0.117 (XGBoost lower). R1 is **not CV-evaluable** (only 7 baseline
  steps, 1 anomaly).
- **SHAP** ranks **descent gradient** and **temperature-linked features** among the
  strongest contributors — supporting the use of *both* mechanical and thermal
  descriptors.
- **Within-participant case study (Patient 350)** reproduces exactly: per-region mean
  peak pressure 65.83 / 69.23 / 63.74 / **138.43** (CV 7.19% / 13.05% / 9.12% /
  **29.17%**) — heel combines high load with high dispersion.

## Reproducibility

A single portable pipeline regenerates the numbers and data-driven figures on Linux,
independent of the original (Windows) acquisition environment.

```bash
# 1. Create an isolated environment
python3 -m venv .venv_linux
.venv_linux/bin/pip install pandas numpy scikit-learn scipy matplotlib seaborn xgboost shap dtaidistance

# 2. Regenerate every reported statistic  ->  repro/canonical_stats.json
.venv_linux/bin/python repro/regenerate_stats.py

# 3. Regenerate the data-driven figures
.venv_linux/bin/python repro/make_figures.py
```

- `repro/regenerate_stats.py` — recomputes cohort flow, descriptive stats, temperature
  cleaning, baseline peak pressure, inter-region correlations, classification CV,
  ANOVA, and the Patient-350 case study → `repro/canonical_stats.json`.
- `repro/make_figures.py` — regenerates the labelled foot-region schematic, inter-region
  correlation, classification-CV, and temperature-distribution figures.
- `repro/PAPER_NUMBERS_AUDIT.md` — line-by-line audit mapping every manuscript number to
  its reproduced value (with provenance notes for values that originate in the
  interactive notebook).
